## 一、清单规则（不可违反）

1. 本清单是 A/C 臂五个模型身份的**唯一依据**；任何字段变更必须先升版方案并更新本清单。
2. **正式运行前必须填齐全部待回填字段**（含回填时间）；未填齐 → SLM_direct 正式门禁不通过。
3. 回填后如哈希与已记录值不一致 → 停止该模型批次、记录差异，不得静默继续或覆盖旧值。
4. 五个模型的 GGUF 转换必须使用**同一 llama.cpp commit、同一转换命令、同一 Q4_K_M 量化**（方案第 13/16 条）。
5. 社区预量化 GGUF 只用于连通性测试（方案第 13 条），其身份不入本清单。
6. 下载时若「主仓库」不存在，改用「备仓库」并在回填表与 JSON 中记录实际使用的仓库。

## 六、执行流程（agent 逐步执行）

### 阶段 1：固定 llama.cpp commit（一次，五模型共用）

```powershell
git -C D:\llama.cpp fetch --all
git -C D:\llama.cpp checkout <最新官方 release tag>   # 例：b6xxx；把 tag 和 commit 都记录
git -C D:\llama.cpp rev-parse HEAD
```

把 `rev-parse` 输出的 40 位 commit 记录为 **llama_cpp_commit**（五个模型必须一致）。

### 阶段 2：逐模型循环（按第二节表格顺序 1 → 5，每模型执行 a–i）

以下命令以模型 1 为例（`<repo>`、`<短名>`、`<model_key>` 逐模型替换）。

**a. 查询并钉住 revision**（主仓库 404/失败则换备仓库，记录实际仓库）：
```powershell
python -c "import requests,sys; repo=sys.argv[1]; r=requests.get('https://modelscope.cn/api/v1/models/'+repo+'/revisions', timeout=60); revs=r.json()['Data']['Revisions']; print(revs[0]['Revision'])" "Qwen/Qwen3-4B-Instruct-2507"
```

**b. 下载（钉住 revision）**：
```powershell
modelscope download --model Qwen/Qwen3-4B-Instruct-2507 --revision <REV> --local_dir E:\models\cet_formal\qwen3-4b-instruct-2507
```

**c. snapshot_manifest_sha256**（口径固定：目录内全部文件按相对路径排序，
生成 `<sha256> *<相对路径>` 清单文件，再对该清单文件求 SHA-256）：
```powershell
$dir = "E:\models\cet_formal\qwen3-4b-instruct-2507"
$manifest = "$dir.snapshot_files.sha256"
Get-ChildItem $dir -Recurse -File | ForEach-Object {
  $rel = $_.FullName.Substring((Resolve-Path $dir).Path.Length + 1)
  "$((Get-FileHash $_.FullName -Algorithm SHA256).Hash.ToLower()) *$rel"
} | Sort-Object | Set-Content -Encoding UTF8 $manifest
(Get-FileHash $manifest -Algorithm SHA256).Hash.ToLower()
```

**d. 转换 f16 GGUF**（同一 llama.cpp、统一命令）：
```powershell
python D:\llama.cpp\convert_hf_to_gguf.py E:\models\cet_formal\qwen3-4b-instruct-2507 `
    --outfile E:\gguf\cet_formal\qwen3-4b-instruct-2507-f16.gguf --outtype f16
```
（报 unknown architecture → `git -C D:\llama.cpp pull` 后重装转换依赖再试；
仍失败 → 停下报告，**不得**用社区 GGUF 顶替。）

**e. 量化 Q4_K_M**（不使用 imatrix → `imatrix_policy=none`）：
```powershell
& <llama-quantize.exe 实际路径> E:\gguf\cet_formal\qwen3-4b-instruct-2507-f16.gguf `
    E:\gguf\cet_formal\qwen3-4b-instruct-2507-Q4_K_M.gguf Q4_K_M
```

**f. GGUF 哈希**：
```powershell
(Get-FileHash E:\gguf\cet_formal\qwen3-4b-instruct-2507-Q4_K_M.gguf -Algorithm SHA256).Hash.ToLower()
```

**g. 导入并加载到 LM Studio**：把 Q4_K_M GGUF 复制到 LM Studio 的模型目录
（LM Studio → My Models 页显示的目录），等待列表出现后：
```powershell
lms unload --all
lms load <LM Studio 里该 GGUF 的原生名> --context-length 4096 --gpu full
```
核对原生接口实际返回的 id（这就是 `served_model_id` 的实测值）：
```powershell
(Invoke-RestMethod http://127.0.0.1:1234/api/v1/models).data | Select-Object id, quantization, context_length
```

**h. capture_deployment.py（可选，可跳过）**：若服务器副本环境方便就执行
（在服务器副本目录执行，会写副本 config.json）；跳过也没关系——本地预检（菜单 1）
会用同一批数值核对并回填正式 config：
```powershell
python D:\cet_slm_direct\capture_deployment.py --model-key qwen3_4b_instruct_2507_base_q4km `
    --gguf-path E:\gguf\cet_formal\qwen3-4b-instruct-2507-Q4_K_M.gguf `
    --revision <REV> --llama-cpp-repo D:\llama.cpp --gpu-offload full
```

**i. 写回填 JSON + 填回填表一行**（JSON schema 见第八节），然后卸载模型，
进入下一个模型。上一个模型执行期间，如果 LM Studio 里同时加载了多个模型，
必须先 `lms unload --all` 再加载下一个（身份预检要求单实例）。

### 阶段 3：交付与自查

1. 核对五个模型的 `llama_cpp_commit` **完全一致**；
2. 核对回填表 5 行齐全、JSON 5 个齐全、字段完整；
3. 报告：每个模型的实际仓库、revision、snapshot 哈希、GGUF 文件名/路径/哈希、
   LM Studio runtime 版本与实测 `served_model_id`、每步是否成功、任何异常与处理记录；
4. 交付物打包：`backfill\*.json` + 本清单回填表（若执行了步骤 h，再附更新后的
   服务器 `config.json` 副本；未执行则不需要）。
